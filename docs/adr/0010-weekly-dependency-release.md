# 0010. 依存の更新だけの週は、パッチ版を機械が出す

- Date: 2026-10-28
- Status: Accepted

## Context

依存の更新は Renovate が PR にする。パッチ版・ダイジェスト・pin の PR は、CI が通れば Renovate 自身がマージする設定にしてある（`renovate.json`、gated と同じ方針）。それでも、マージされた更新がイメージの版になるのは、人が `v*` のタグを打ったときだけだった（ADR 0008）。依存の更新しか入っていない週に、人が版を選び、タグのメッセージを書く理由は無い。書くことが「依存を上げた」しか無いからである。

一方で、人が書いた変更を機械がリリースしてはいけない。機能の変更は、何を入れたかを人がタグのメッセージに書いて出す。

gated（ADR 0036）と fraction-agents（ADR 0024）は、同じ Renovate の GitHub App のもとで、この問題を同じ規則で解いている。vuln-tracker も同じ規則に揃える。gated と同じく Go のリポジトリなので、判定も gated と同じ形で Go に置く。

## Decision

### 前回の版から Renovate のコミットしか無ければ、週に一度パッチ版を出す

`release` のワークフローが週に一度（月曜 09:00 JST）と手での起動（workflow_dispatch）で、main に対してだけ動く。最新の版タグから main の先頭までが次の 2 つを両方満たすとき、パッチ版を 1 つ上げた版タグを打つ。

| 条件 | 見るもの | 満たさないとき |
|---|---|---|
| マージ以外のコミットの作者がすべて `renovate[bot]` | 最新の版タグから先頭までのコミット | 人の変更が 1 つでもあれば何もしない。リリースは人が打つ |
| イメージの中身に関わるファイルが変わっている | 同じ範囲の差分 | ワークフロー、`renovate.json`、`config/`、テストの足場だけの更新ではリリースしない |

イメージの中身は Dockerfile とそれがコピーするもの（`go.mod`・`go.sum`・`cmd/`・`internal/`）である。trivy のバイナリは Dockerfile の中で版を指しているので、その更新も Dockerfile の変更として数える。

どちらかを満たさなければ、何もせずに成功で終わり、理由をログに残す。人がタグを打てば、そこからまた数え直しになる。

最新の版タグは `vX.Y.Z` の形のものだけを、数として比べて選ぶ。版タグが 1 つも無ければ何もしない。

判定は `hack/release-plan` に置き、`make release-plan` で手元からも同じ問いを発せる。判定そのものは git に触れない純関数で、表駆動のテストで固める（ADR 0008 のテストの層の 1 段目）。

### 機械が打つタグも注釈つきにする

1 行目は版と「依存の更新」であることを書き、本文に含まれる Renovate のコミットの件名を並べる。

### イメージを先に push し、タグは後から打つ

実行ごとに発行されるトークンで push したタグでは、ほかのワークフローが起動しない。したがって機械がタグを打っても、`publish` のワークフローはそのタグのイメージを出さない。

`release` は `publish` を workflow_call で呼び、これから打つ版の名前でイメージを push し、それが成功してからタグを打つ。`publish` は呼ばれたときもテストを先に走らせる。イメージの push に失敗すればタグは残らない。呼ばれたときは untagged の版の掃除はしない。掃除の失敗でタグが打たれなくなることを避けるためである。

人が版タグを push したときと main への push は、これまでどおり `publish` がそれぞれの ref で動く。

### 書き込む権限は書き込むジョブにだけ持たせる

`release` の先頭は読み取りのみとし、パッケージへの書き込みは `publish` を呼ぶジョブに、リポジトリへの書き込みはタグを打つジョブにだけ与える。どちらのワークフローも PR では起動しない。

## Consequences

- パッチ版とダイジェストの更新は、人の手を経ずに main に入り、依存の更新しか無い週にはイメージの版になる。本番で使う版は fleet-infra が pin しているので、本番に入れるのは fleet-infra の側の仕事のままである
- ADR 0008 の「`v*` のタグでそのタグのイメージを出す」は変わらない。版タグを打つのが人だけではなくなり、「人の変更を含む版タグは人が打つ」に狭まった
- 人の変更と Renovate の更新が同じ週に入ると、その週の依存の更新は人のリリースを待つ。この ADR を入れる変更そのものも人のコミットなので、次に人が版タグを打つまで機械はリリースしない。意図した動作である
- Renovate のブランチに人がコミットを足した場合も、そのコミットは人のものとして数えられ、機械はリリースしない
- Go の tool ディレクティブだけの更新も `go.mod` を変えるので、バイナリが変わらなくてもパッチ版が出ることがある。gated と同じく区別しない
- main の先頭そのものの CI の結果は見ていない。Renovate のコミットは CI が通らなければマージされないこと、`publish` が push の前にテストを走らせることで代える
- 自動のリリースを止めたいときは、`release` のワークフローを無効にすればよい
